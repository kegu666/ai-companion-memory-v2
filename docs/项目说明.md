# AI Companion Memory V2 项目说明

这是基于 [pinganbbOvO/ai-companion-kit](https://github.com/pinganbbOvO/ai-companion-kit) 制作的记忆增强试验版。
目标是让陪聊机器人在上下文长度有限的情况下，保存完整聊天、压缩较早对话，并找回相关的长期记忆。
保留上游代码及 MIT 许可证；详细技术配置见 [MEMORY-V2.md](MEMORY-V2.md)。

## 为什么这样设计

把所有历史聊天塞给模型，输入会越来越长，也会增加延迟和调用成本。
只保留一份不断改写的摘要，又容易丢掉细节，或把“打算搬家”误记为“已经搬家”。

本版把完整原文、历史摘要和已确认记忆分开保存：原文用于追查，摘要用于保持话题连续，长期记忆用于检索人物偏好和事实。
这能提供可核对、可纠正的记录，但不能保证模型永远不会错记。

## 一轮聊天如何处理

1. 收到消息后，将完整来信、作者、会话和时间写入 SQLite。
2. 取当前会话的近期原文、历史摘要和相关的已确认记忆，交给聊天模型生成回复。
3. 保存生成的回复，并单独记录是否成功发送，避免把“生成过”当作“对方收到过”。
4. 后台整理较早对话，更新摘要，同时提取候选记忆；最近几条继续保留原文供模型阅读。
5. 检查候选的来源编号、原话和作者。候选需由本地管理者明确确认，才参与长期记忆检索。

默认保留最近 8 条原始记录；未压缩记录达到 20 条或文本达到 12000 字符时触发整理。
压缩只改变提供给模型的历史视图，数据库里的完整原文不会因此删除。

## 三类模型分别做什么

| 角色 | 工作 | 是否可以共用 |
| --- | --- | --- |
| 聊天模型 | 生成正常回复 | 可以和整理模型共用同一个模型及服务 |
| 整理模型 | 生成摘要、提取候选记忆 | 可独立配置，不必额外部署一套模型 |
| Embedding 模型 | 把问题和记忆变成向量，支持语义匹配 | 需要支持 embeddings 接口的模型 |

向量存在 SQLite 中，程序计算余弦相似度，并结合关键词匹配。
不需要先搭独立向量数据库。Embedding 不可用时退回关键词检索；没有整理模型时不会自动压缩或提取记忆。
整理在后台进行，会额外调用模型，延迟和费用取决于配置的服务。

## 事实更正和隐私边界

例如先确认“住在深圳”，后来又确认“已经搬到上海”，两条记忆使用同一个 city 字段时，旧记录会退役，新记录参与检索。
来源和替代链仍保留。字段名需要检查；目前没有自动解决所有自然语言事实冲突的能力。

私聊、不同群聊分别保存和检索，不默认把私聊资料带进群聊。
这是本地程序的会话隔离，并不是面向公网的多租户权限系统。
数据库为明文；接真实模型后，选入上下文的聊天资料会发送给配置的模型服务。
“遗忘”命令只移除检索记忆，不会彻底擦除原文和历史摘要。

## 先运行离线演示

需要 Node.js 22.13 或更新版本。在仓库根目录执行：

~~~powershell
npm.cmd run memory:demo
~~~

Windows 也可直接双击 `tools/memory-v2-demo.cmd`。
无需 QQ、API Key 或数据库服务，也无需安装 npm 依赖。

演示会展示原文入库、历史压缩、候选确认、事实替代和私聊隔离，结果放在 `data/memory-v2-demo-时间戳/`。
**演示使用固定摘要和人工测试向量，只证明程序链路可运行，不代表真实模型的记忆准确率。**

## 接入真实模型试聊

1. 复制 `packages/companion/config.memory-v2.example.json` 为同目录下的 `config.json`。
2. 按服务实际接口填写聊天模型、整理模型和 embedding 的地址及模型名称。
3. 在当前终端用环境变量设置 API Key，避免把密钥写入仓库。
4. 在仓库根目录运行：

~~~powershell
node packages/companion/src/memory-chat.js --config packages/companion/config.json
~~~

此入口可直接在终端试聊，不依赖 QQ。聊天与整理要求 Chat Completions 接口；embedding 要求 embeddings 接口。
程序不会自动读取 CC Switch 中的配置或密钥。

试聊时，`/compact` 强制整理较早对话，`/memories` 查看记忆，`/approve 编号` 确认候选，`/search 问题` 检索已确认记忆。
消息数量超过保留的近期条数后，才有可压缩的旧消息。完整配置和命令见 [详细文档](MEMORY-V2.md)。

## 已完成和待验证

已实现 SQLite 存储、后台压缩队列、候选来源校验、确认及替代、混合检索、会话隔离、旧 JSON 数据迁移和模型故障回退。
17 项自动化测试通过，覆盖本机模拟 HTTP 接口调用；离线演示和数据库完整性检查通过。

尚未完成真实模型准确率评估、真实 QQ 收发验收、长期运行压测和可视化管理页面。
很长的单条消息在整理时会提供摘录，递归摘要也可能丢失细节；完整原文保留在数据库中供追查。

改造范围是原项目自带的 `packages/companion` 聊天入口。
原项目安装脚本下载的第三方 `qq-bridge` 不会自动获得这些能力，需另外适配；也没有改动 DSH 的原生记忆。
当前版本适合本地试用和继续开发，不应直接当作已经完成生产验收的陪聊服务。
